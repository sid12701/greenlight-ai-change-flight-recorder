# Official hackathon requirements

Sources were checked on 26 July 2026.

## Mandatory

- Submit by **26 July 2026, 05:29 IST**.
- Build a project that integrates SigNoz.
- Select one track; GreenLight uses **Track 3 — Build Your Own**.
- Team size is one to four.
- AI tools are permitted, but their use must be disclosed.
- The public repository must include `casting.yaml` and `casting.yaml.lock`.
- The form requires a project description, GitHub URL, a new detailed project
  blog URL, a YouTube demo URL of no more than three minutes, an explanation of
  SigNoz usage, and a hackathon-experience response.
- Only one team member submits.

## Recommended by the organizers

- Use Query Builder, dashboards, alerts, and/or MCP meaningfully.
- Write an authentic, technically tested blog with screenshots.
- Keep the video focused on the project, stack/architecture, and working demo.
- Make the repository reproducible through SigNoz Foundry.

## Inferred presentation priorities

The published judging criteria reward potential impact, creativity and
innovation, technical excellence, best use of SigNoz, user experience, and
presentation. GreenLight’s strongest evidence is therefore the complete
baseline/candidate/recovery chain, the 7.3× receipt, the version-grouped
dashboard, resolvable traces, alert history, and explicit limitations.
